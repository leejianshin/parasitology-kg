# Phase 6：华支睾吸虫学生RAG验收

本阶段验证第一批正式知识子图能否改善学生使用AI工具时的准确性、可追溯性、
关系理解和边界控制。本阶段不是再做医学事实检索，也不通过模型常识补齐尚未准入
的知识。

## 本轮施工范围

- 冻结18个问题：11个应回答、3个应部分回答、4个应拒答；
- 生成只含P5-B1正式内容的白名单RAG语料包；
- 固定baseline与RAG的成对比较条件；
- 定义统一回答记录合同；
- 建立机器校验和教师评分双层门槛；
- 保持P5-B2、P5-B3及学生发布未授权。

## 为什么必须测试拒答

P5-B1当前只覆盖传播行为、寄生部位、胆道病理位置、轻感染表现、诊断线索和基础
干预。第一中间宿主、治疗、IARC分类和病原学确诊尚未正式准入；当前语料虽可支持
“摄入含活囊蚴的淡水鱼可导致感染”，但尚未建立正式的感染阶段关系，也不足以
比较淡水鱼与淡水虾的第二中间宿主权重。因此，后两类问题只能回答已有部分并明确
缺口，其余越界问题应拒答。RAG若凭模型记忆补全缺口，即使医学常识碰巧正确，也
属于语料边界失守。

## 执行方法

1. 使用同一工具、同一模型和同一版本分别运行baseline与RAG；
2. 每个问题都使用独立干净会话，并关闭网页搜索和外部记忆；
3. baseline不加载仓库，RAG只加载`phase6-rag-corpus`白名单中的两个文件；
4. 不得直接加载整个GitHub仓库、来源总表、候选稿、评审记录或Phase 6题集；
5. 按`test-cases.yml`原顺序提问，不在运行中修改题目；
6. 按`phase6-rag-run-template.yml`记录回答、实体、关系和来源；
7. 先运行机器校验，再由学科教师按`teacher-rubric.yml`评分；
8. 达到绝对门槛并优于baseline后，才可提出学生试点发布建议。
