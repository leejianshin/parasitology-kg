# 系统工作流与阶段目标

## 总体原则

项目采用“小规模试点—人工验收—再扩展”的方式推进。任何阶段未通过验收，不进入下一阶段；不得以批量生成掩盖结构或事实问题。

正式知识的流转路径为：

> 原始来源登记 → 双路候选提取 → 来源核对与冲突处理 → 教师审核 → 结构化入库 → 自动校验 → RAG测试 → 发布

## Phase 0：治理框架冻结

### 目标

确定项目究竟建设什么、服务谁、One Health 如何发挥组织作用，以及每个阶段怎样验收。

### 主要工作

- 明确项目定位和第一目标；
- 明确公开仓库与原始资料的边界；
- 明确AI提取、技术整理和教师审核的权责；
- 建立阶段工作流和停止条件；
- 将旧三元组文件标记为历史PoC。

### 交付物

- `README.md`
- `docs/PROJECT_SCOPE.md`
- `docs/WORKFLOW.md`
- `docs/STATUS.md`
- `archive/poc-2025/triples.csv`

### 完成标准

- 目标、边界和首个试点无实质歧义；
- 每个后续阶段都有明确输入、输出和验收条件；
- 框架经项目负责人确认后合并进入 `main`。

## Phase 1：Schema与编辑规范

### 目标

规定什么是实体、什么是关系、结构化Markdown如何书写，以及来源和审核状态如何记录。

### 主要工作

- 定义实体类型和唯一ID规则；
- 定义受控关系词表及方向；
- 定义来源、页码、证据和审核字段；
- 区分事实、推断、关联和治理建议；
- 建立结构化Markdown模板；
- 规定中文名、英文名、拉丁名和同义词写法。

### 交付物

- 实体类型表；
- 关系类型表；
- 来源登记Schema；
- 实体Markdown模板；
- 编辑与引用规范；
- 最小校验规则。

### 完成标准

- 同一事实由不同人员提取时能够落入相同字段；
- 第一中间宿主、第二中间宿主、终宿主和保虫宿主不会被同一宽泛关系替代；
- 每个关键关系可以指向来源；
- 模板同时适合人读和机器解析。

### 停止条件

如模板仍依赖自由发挥、关系词存在明显歧义或来源无法落实到关键事实，不进入语料提取。

## Phase 2：华支睾吸虫来源集冻结

### 目标

为试点选定数量有限、角色明确的来源，避免在提取过程中不断扩大范围。

### 主要工作

- 登记拟使用的教材、个人课件、大纲、题库和扩展资料；
- 给每份来源分配稳定 `source_id`；
- 记录版本、年份、文件角色和可定位信息；
- 确定核心来源与补充来源；
- 标记无法公开全文的版权材料。

### 建议首批来源

- 一部当前使用的权威中文教材；
- 一份本人当前理论课件；
- 一份相关课程教学大纲；
- 题库或学习指导中的华支睾吸虫内容；
- 必要时增加一至两份权威 One Health 或防控资料。

### 交付物

- 华支睾吸虫试点来源清单；
- 来源角色说明；
- 检索范围和版本冻结记录。

### 完成标准

- 每份来源都能被唯一识别；
- 核心事实、教学重点和One Health扩展分别有合适来源；
- 不再以“整个Drive文件夹”作为模糊来源。

## Phase 3：双路候选提取

### 目标

使用相同模板分别提取候选语料，以发现遗漏、误读和结构问题。

### 路线A：NotebookLM/Gemini

- 由用户指定来源和固定Prompt；
- 输出结构化候选内容；
- 保留NotebookLM给出的来源定位；
- 不直接提交到正式知识目录。

### 路线B：独立文件提取

- 从用户指定并提供的原始文件中独立提取；
- 按同一Schema拆分实体、关系和说明文本；
- 记录来源页码、幻灯片或章节；
- 不读取NotebookLM结论后再反向迎合。

### 交付物

- 两份独立候选提取；
- 提取缺失项清单；
- Schema适配问题清单。

### 完成标准

- 两条路线使用同一来源范围和同一模板；
- 每条候选关系均说明其来源；
- AI补写、无来源扩展和不确定项已被明确标记。

## Phase 4：对照、冲突处理与教师审核

### 目标

把候选语料转化为经审核的知识，而不是简单拼接两份AI输出。

### 主要工作

- 对照两路结果的一致项、遗漏项和冲突项；
- 回到原始来源裁决；
- 处理教材版本差异和课件简化表达；
- 区分本科核心知识与扩展知识；
- 审查One Health关系是否被夸大；
- 由学科教师作最终批准。

### 交付物

- 对照审计表；
- 冲突与处理记录；
- 教师批准的事实和关系清单；
- 未决问题清单。

### 完成标准

- 不以“两个AI都这样说”作为证据；
- 每项冲突都有处理结果或保留为未决；
- 教师确认知识口径适合学生使用。

## Phase 5：华支睾吸虫知识子图入库

### 目标

将审核结果写成正式结构化Markdown，并生成可计算图数据。

### 主要工作

- 创建华支睾吸虫及相关实体文件；
- 建立生活史、宿主、环境、行为、疾病、诊疗和防控关系；
- 为关系挂接来源；
- 生成CSV/JSON等派生数据；
- 检查断链、重复ID和非法关系。

### 交付物

- 华支睾吸虫中心节点；
- 配套宿主、发育阶段、环境、行为和干预节点；
- 自动生成的三元组或图数据；
- 校验报告。

### 完成标准

- 正文与结构化关系不存在实质矛盾；
- 所有引用ID可解析；
- 关键关系均可追溯；
- 派生数据能够从主数据重新生成。

## Phase 6：学生RAG验收

### 目标

验证知识子图是否真正改善学生使用AI工具时的准确性、可追溯性和关系理解。

### 测试组

1. 基础事实题：形态、生活史、宿主和感染阶段；
2. 关系查询题：共享宿主、传播途径和环境条件；
3. One Health综合题：人—动物—环境传播链；
4. 防控题：不同环节的干预及其边界；
5. 来源题：要求返回支撑结论的来源；
6. 陷阱题：故意混淆宿主类型、感染阶段和因果关系。

### 交付物

- 固定测试问题集；
- 基线回答与RAG回答对照；
- 错误类型记录；
- 是否适合向学生发布的结论。

### 完成标准

- 核心事实和宿主角色无严重错误；
- 回答能够返回来源；
- 对资料未覆盖的问题能够承认不足；
- One Health回答不把关联误写为因果；
- 教师批准试点发布。

## Phase 7：发布与扩展决策

### 目标

发布首个稳定版本，并依据试点结果决定是否扩大到其他寄生虫。

### 主要工作

- 给华支睾吸虫试点建立版本标签；
- 编写学生使用说明和限制说明；
- 决定下一类寄生虫及扩展顺序；
- 评估是否需要网站、图数据库或自动化流水线；
- 只自动化已经稳定的人工流程。

### 完成标准

- 首个版本可被学生稳定获取；
- 使用方法、适用范围和限制清楚；
- 下一阶段扩展依据实际测试结果，而非工具展示效果。

## 全流程变更规则

- 正式知识变更通过分支和Pull Request进入主分支；
- 原始AI输出不得直接合并；
- Schema变更必须说明对现有数据的影响；
- 关键事实修订必须保留原因和来源；
- 批量操作前必须先通过小规模样本验证；
- 任何阶段发现严重事实或结构问题，回退到对应上游阶段处理。
